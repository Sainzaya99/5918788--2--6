# 과제 06: 순차 탐색, BST, AVL 트리의 성능 비교

## 1.

난수를 사용하기 때문에 실행할 때마다 결과가 조금씩 다릅니다. 아래 내용은 한 번 실행한 결과입니다.

비교 횟수는 저장된 값(배열의 원소 또는 트리의 노드) 하나와 비교할 때마다 1회로 셌습니다. 중복이라서 삽입하지 않은 경우의 비교도 포함했고, AVL 트리의 높이 계산과 균형 확인은 포함하지 않았습니다.

## 2. 실행 결과

**저장 결과**

| 항목 | 값 |
|---|---|
| 실제로 저장된 서로 다른 값의 수 | 88 |
| 중복으로 삽입되지 않은 값의 수 | 12 |

**생성 과정의 비교 횟수와 크기**

| | 배열 | BST | AVL 트리 |
|---|---|---|---|
| 생성 비교 횟수 | 4,226 | 650 | 514 |
| 배열 길이 / 트리 높이 | 88 | 13 | 8 |

**탐색 결과 (탐색 대상 50개, 성공 5개 / 실패 45개)**

| | 순차 탐색 | BST 탐색 | AVL 탐색 |
|---|---|---|---|
| 총 비교 횟수 | 4,125 | 424 | 325 |
| 평균 비교 횟수 | 82.50 | 8.48 | 6.50 |

## 3. 분석

**BST와 AVL 트리의 높이가 다른 이유**

같은 88개의 값을 같은 순서로 넣었는데 BST의 높이는 13, AVL 트리의 높이는 8이었습니다. BST는 들어온 순서대로 붙이기만 하기 때문에 한쪽 가지가 길어질 수 있습니다. AVL 트리는 삽입할 때마다 왼쪽과 오른쪽 높이 차이를 확인하고, 차이가 크면 회전해서 균형을 맞추기 때문에 높이가 낮게 유지됩니다.

**높이가 탐색 비교 횟수에 미치는 영향**

트리에서는 한 단계 내려갈 때마다 1번 비교하므로, 높이가 낮을수록 비교 횟수가 줄어듭니다. 이번 실험에서 AVL 트리의 평균 비교 횟수(6.50)가 BST(8.48)보다 약 2회 적었습니다. 높이가 5 낮아진 것이 탐색 속도 차이로 나타난 것입니다.

**순차 탐색과 트리 탐색**

순차 탐색은 값이 없으면 배열 전체(88개)를 비교해야 합니다. 이번에는 탐색 대상 50개 중 45개가 없는 값이어서 평균이 82.50으로 매우 컸습니다. 트리는 한 길만 따라 내려가기 때문에 평균이 8.48, 6.50으로 훨씬 작았습니다.

**생성 비용과 탐색 비용 비교**

| | 생성 비용 | 탐색 비용 | 설명 |
|---|---|---|---|
| 배열 | 가장 큼 | 가장 큼 | 매번 처음부터 끝까지 비교해야 함 |
| BST | 중간 | 중간 | 한 길만 내려가지만 높이가 커질 수 있음 |
| AVL 트리 | 가장 작음 | 가장 작음 | 균형을 유지해서 높이가 낮음 |

AVL 트리는 비교 횟수는 가장 적었지만, 삽입할 때 회전과 높이 계산을 해야 해서 구현이 더 복잡합니다.

## 4. 결론

데이터를 찾는 데 걸리는 비교 횟수는 트리의 높이와 관계가 깊고, 균형을 유지하는 AVL 트리가 이번 실험에서 생성과 탐색 모두 가장 적게 비교했습니다.
